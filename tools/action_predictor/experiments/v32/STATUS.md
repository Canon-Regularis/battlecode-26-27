# Contiguous-history data preparation

GPT-6 Astra at medium reasoning recommended validating longer eligible personal
trajectories before fitting another strategic architecture. Its full research
memo and cited primary papers are preserved in `astra-research.json`.

The original chronological-cap audit did not meet the unchanged feasibility
gate: 543 fitting and 182 assessment windows of 32 consecutive own roots. Its
plans, results and two validator implementation failures remain preserved.

An availability-only selection of complete, nonoverlapping windows meets that
same gate using 42,010 additional cached roots, within the original 100,000-root
budget and the same 60 games and group partitions. It supplies 1,085 fitting
windows across 40 groups, 273 tuning windows across ten groups and 280 assessment
windows across ten groups. All counted windows cross round boundaries. Existing
selected roots in these games remain retained. This selection enriches long
available contexts; it is not natural-cadence sampling.

All proposed roots passed recorded-command and personal-PRE binding checks;
selected command types, coordinates and canonical priority integers agree.
Validated window topology exactly reproduces the availability-only proposal.
The final manifest is `window-validation.json`. No training arrays or new fits
have been created, and both reserved partitions remain sealed.

These checks do not establish new POST/outcome validation, full legality,
unambiguous entity targets, shop purchase arguments or strategic benefit. The
partitions use previously researched TRAIN groups, not untouched certification
data. Any new fit must use fitting-group-only preprocessing and components;
previously trained M01/P05/RC01 weights cannot silently supply a clean holdout.

Independent review of the data preparation is pending. After review, the next
step is feature/history parity and an explicit matched protocol separating
recurrent memory access from longer gradient credit assignment. Optimization
requires its own reviewed protocol; passing this data gate is not performance
evidence.
