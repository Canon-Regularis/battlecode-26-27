# Why 1,301 commands are unavailable, and why TRAIN rescue is only 13.2%

These are two different failures. The first is largely a demonstrable restriction of the command generators and hard fallback. The second combines a conservative/mismatched router with genuine action and parameter ranking failures. This follow-up uses existing artifacts and recorded personal PRE evidence; **no fit was run**.

## 1. Where the 1,301 unsupported DEV commands come from

The denominator is every original DEV row. “Unavailable” means that neither the frozen C00 simple point library nor G00's single hard forecast equals the complete recorded benchmark command. It does not mean that no earlier model, conditional head or possible algorithm can produce it.

| Actual family | Missing commands | Demonstrated restriction |
|---|---:|---|
| Priority | 505 | All targets are nonzero. On 500 rows the only point proposal is zero; on 5 rows missing position makes the entire point library abstain. |
| Move | 409 | The five goals, declared costs and selected tie rules do not emit the recorded step; detailed compatibility analysis below. |
| Cast 1 | 118 | 106 ground-only targets have no ground-target branch; 1 mixed ground/unit target is outside compatible unit proposals; 11 eligible targets lose under the three target ranks. |
| Blocked attempt | 102 | The library emits no `blocked` outcome at all. G00 is its only possible source. |
| Ward | 100 | 88 targets are two cells away; the library proposes self or one step toward the bank. The other 12 one-cell targets are not that chosen direction. |
| Shop | 43 | Original item/count arguments remain unavailable and unassessed strict failures. No purchases are invented. |
| Attack | 13 | 9 eligible targets are absent from nearest/lowest-HP/lowest-fraction choices; 4 targets expose an omitted observable entity category. |
| Cast 0 | 7 | The recorded eligible target is not selected by those three rankings. |
| Altar | 2 | No point generator for this action family; G00 chooses the wrong type. |
| Teleport | 2 | No point generator; G00 emits the type with the wrong parameter. |
| **Total** | **1,301** | |

This is principally inadequate hypothesis coverage, not demonstrated randomness in Fish.

### Priority, ward and blocked commands are restricted by construction

The priority branch is a constant-zero proposal, not a learned algorithm for the recorded integer. Better routing cannot make it output another value. Missing position also unnecessarily suppresses utility proposals, including five of these priority cases.

All 100 missing ward rows have a charge available. Thus absence of a charge does not explain their omission. Their offsets explain it directly: 88 have Chebyshev offset 2 and 12 offset 1. Earlier read-only pinned-engine queries established placement range 2; the library omitted most of that directed-placement mechanism. This does not reveal Fish's intended coverage objective or establish the availability of existing ward positions.

For 88 of the 102 missing blocked attempts, the current movement mask is empty and the movement flag is unavailable. The recorded attempted destination and blocked outcome still matter. A library constrained to successful movement destinations and without a blocked-outcome generator cannot represent those commands. This is not an illegal-successful-move claim. C02's TRAIN-only repair shows this mechanism matters, but no C02 DEV accuracy is claimed here.

### Movement: restricted objectives/costs/ties, with a remaining unexplained set

Among these specific 409 missing moves, the retained R01 diagnostics identify:

- **185** compatible with an alternative greedy optimum across the tested goal family;
- **77** additional moves compatible with the tested terrain-field optimum;
- **147** unexplained by those progress/optimality sets.

These counts are compatibility statements, not definitive tie/pathfinding/hidden-intent cause labels. They narrow what is missing without assigning Fish an oracle goal. The historical first-step movement mask does not uniquely identify the correct objective or tie.

There is also a concrete library-selection loss: **65 of the missing commands already appear in the retained C00 terrain-library predictions**, which A00 cannot choose because its entire library was replaced by the geometric TRAIN winner. The global coverage comparison did not preserve every complementary component. This is an oracle diagnostic of an existing excluded hypothesis, not achieved ensemble accuracy or permission to enumerate destinations.

### Four attacks expose a specific missing observable entity category

The four attacks without a matching champion/camp target all point at public altar cells. Four read-only restorations of their exact recorded PRE states, using the correct personal actor/team API and pinned engines, return enemy **altar locks, entity kind 6**, at those coordinates. The original observation/candidate representation includes champions and camps, not those locks.

This is stronger evidence than a generic “some information might be missing”: a relevant target category is personally queryable but omitted. One cell contains both allied and enemy locks, so target coordinates still do not uniquely certify the original attacked entity ID. The result explains a missing category of proposals; it does not fabricate an ID label. See [the targeted API receipt](U00-target-kinds.json).

### Some missing commands are caused by type/argument coupling

On **135 of the 1,301 rows**, G00's oracle-conditioned parameter head supplies the correct benchmark argument, but G00 chooses another action type. These comprise 38 priority, 31 move, 27 cast-1, 17 ward, 16 blocked, 4 attack and 2 altar rows.

A00 cannot combine a different action choice with that conditional argument: the fallback is G00's complete hard forecast, while point candidates supply only their own restricted arguments. Consequently the complete command remains unavailable even though an existing conditional head can provide its parameter.

This is **not** an actual forecast and does not use the current true family at inference. It is a diagnostic capability overlay. It must not be added to the main missing-category table as a second disjoint bucket. Overall, 129 missing rows lack the true family in either point outputs or G00's hard forecast; 1,172 emit the family somewhere but lack a strict-correct complete command. For shops, that latter count includes unassessed arguments, not known wrong purchases.

Existing M01/P05/G01 hard forecasts also match 22/15/22 of these missing rows, respectively. These counts overlap and are not summed or promoted. “Unavailable to A00” is narrower than “all previous approaches fail.”

## 2. Where the 13.2% natural-TRAIN rescue rate comes from

There are exactly **28,903 natural TRAIN rows where G00 is wrong and at least one point candidate is correct**. No shop or unsupported case enters that rescue denominator. The exact partition is:

| Outcome on these opportunities | Rows | Share |
|---|---:|---:|
| A00 rescues the command | 3,814 | 13.20% |
| Correct command ranks first among point commands, but fallback overrides it | 15,422 | 53.36% |
| Wrong global action choice among points, although the correct command wins within its true family | 3,980 | 13.77% |
| Wrong parameter/command wins even within the true family | 5,687 | 19.68% |
| **Total** | **28,903** | **100%** |

The known-family split is an explicitly oracle-conditioned ranking diagnostic, not a forecast. It preserves multiple matching candidates and invents no “true algorithm” label.

Thus **19,236/28,903 (66.55%)** already rank the correct command first within the point branch, but only 3,814 are emitted correctly. Of the remaining 25,089 unrescued opportunities, 15,422 are correct-top-point vetoes and 9,667 genuinely rank another point command first. In the latter group, the router uses G00 on 9,461 and selects the wrong point command on 206.

The mix is different for different actions:

| Family | Rescue opportunities | Rescued | Correct point vetoed | Wrong global action rank, correct within family | Wrong within-family parameter rank |
|---|---:|---:|---:|---:|---:|
| Move | 11,936 | 764 | 5,389 | 487 | 5,296 |
| Recall | 11,012 | 2,436 | 7,969 | 607 | 0 |
| Attack | 1,631 | 439 | 585 | 394 | 213 |
| Cast 0 | 739 | 8 | 12 | 589 | 130 |
| Cast 1 | 387 | 1 | 2 | 336 | 48 |
| Ward | 76 | 0 | 0 | 76 | 0 |

For recall, the correct point command is already ranked first on 10,405/11,012 opportunities. For movement, only 6,153/11,936 have the correct global point ranking; 5,296 still rank a wrong destination even if action type were known. Fixing only the fallback will not solve that movement ranking problem. The 76 ward rescue opportunities are entirely global action-ranking failures in this diagnostic.

### The loss and hard decision rule give fallback different meanings

The fitted probability of the recorded command is:

`point weight on that command + fallback weight × G00 probability of that command`.

The hard router instead compares the whole fallback weight against a single point-command weight. As established in the previous investigation, this can discard a correct preference. It does not mean every correct-top-point veto is a probability-ranking error; the teacher's full distribution may legitimately favor a competing command. The already frozen D00 decoder demonstrates a limited net improvement, with important category regressions, rather than a universal repair.

There is a second structural pressure. When no point candidate matches a training target, the mixture loss reduces to:

`loss = −log(fallback weight) − log(G00 probability of the recorded target)`.

For the fallback logit, the derivative is `fallback weight − 1`. Gradient descent therefore increases fallback weight—even when G00's hard output is not strict-correct. The soft distribution can assign probability to the observed target while the hard decoder cannot emit it. This also applies to observed shop-type likelihood without recovering purchase arguments.

This is not missing supervision: it is what the specified objective mathematically requests. A sufficiently expressive conditional selector could still learn different behavior on different rows. It does show why interpreting fallback weight as “G00's hard command is correct” is inappropriate.

### The optimizer sees many more situations than the rescue subset

Across all 433,071 augmented training rows, the exposure is:

| Situation | Rows | Share |
|---|---:|---:|
| G00 and a point command both strict-correct | 303,410 | 70.06% |
| A point command could rescue G00 | 37,915 | 8.75% |
| Only G00's hard command strict-correct | 26,649 | 6.15% |
| Neither hard option strict-correct | 65,097 | 15.03% |

The last category includes unassessed shops; it must not be described as 65,097 proven wrong purchase/action arguments. It is a strict benchmark accounting category.

The augmentation-only rows have **28.70% neither-option support**, versus **8.20%** in the natural subset. Thus the optimization exposure is not the same as the natural rescue diagnostic. This is an observed task-mixture difference, not proof that augmentation caused failure.

At the selected scores, the 65,097 neither-option rows contribute approximately −.01463 to the overall fallback-bias derivative, opposing the +.01384 from rescuable rows. Teacher-only rows also favor fallback; rows where both options work contribute differently. These are local analytic pressures, not a causal optimization intervention. They show how a global loss can keep fallback dominant while a useful repair remains unselected. The previous gradient/saturation measurements do not prove which feature or optimizer change would resolve the remaining fitting error.

### Removing fallback is demonstrably unsafe

A new no-fit control forces the highest-weight point command whenever any point is available, retaining G00 only when none exists. On the original natural TRAIN denominator it fixes 15,422 A00 errors but introduces **65,782 regressions**. Accuracy falls from A00's 83.03% to **65.59%**. Rescue capture becomes 66.55%, but that conditional statistic conceals a large overall loss.

The required problem is conditional routing: recover errors without destroying the much larger set where fallback or an already-correct choice is valuable. Neither “always use G00” nor “always take the best algorithm candidate” solves it.

## What is established, and what remains unresolved

The 1,301 misses are largely explainable generator restrictions, including nonzero integers, ground targeting, placement distance, outcome types, target categories and a hard type/argument coupling. Movement still includes genuinely unexplained objective/cost/tie behavior; no Fish intent is inferred from its destination.

The 13.2% rate is not evidence that training supplied no answer. Much of the correct point ranking is already present, but the hard router suppresses it. The residual 9,667 point-ranking failures split into action choice and parameter choice, and occur on TRAIN itself. Loss exposure and its fallback gradient are now quantified, but it remains unproven how much limited inputs, initialization, capacity, sampling or optimization causes those residual rankings.

These results justify repairing the train/decision contract and testing the remaining causal selection information with matched controls. They do not justify another unstructured architecture phase, an oracle decoder, a new blanket fallback threshold or promotion of D00. Production training remains paused. All original DEV rows and historical artifacts remain unchanged; both reserved partitions remain sealed.
