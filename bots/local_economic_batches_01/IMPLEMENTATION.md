The hypothesis is that repeated per-getter guards consume enough engine fuel to prevent capture/planning admission. LiveTurn::capture_reads uses a separate noncopyable reader with a runtime maximum of eight explicit public wrapper calls per batch. It charges queries_issued before each attempted getter and queries_completed only after normal return, checks both counters for overflow, and seals before a ninth getter. The entry/exit guard reads full epoch, fuel, full epoch again; it rejects a changed actor/life/round/revision, including rollover during the fuel query. It samples the original shared ledger and retains reserve5000. Expected and unexpected exceptions cross the same closing guard before propagating. Destructors do no SDK work.

All bitboard/native masks, group.state, ability reads, hidden sibling checks, ordinary LiveTurn::read and all action preflight/mutation code remain inherited. No observation is deliberately omitted and no policy, draft, reserve, field admission or storage capacity changes.

The original capture start/final epoch checks, lifecycle/cache publication and pending-receipt patch proof remain. Scratch writes are provisional until capture completes. Batching is not atomic: after suspension, up to seven additional pure public getters can run before closing validation rejects the batch. SDK errors can allocate diagnostics before the catch; no universal error-cost/reserve bound is claimed. Native success and fewer guard imports do not qualify engine activity, total memory/fuel admission, economic completion or competitive strength.
