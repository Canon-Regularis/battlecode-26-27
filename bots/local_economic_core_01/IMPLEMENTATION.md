# Local economic strategy core 01

This is a LOCAL PC implementation, derived from recovery-cost-02 source
`b5aee40dd36283c318b3b3d16df46f70f17c1ead`. That parent was rejected as a
standalone recovery revision. This draft is neither the ranked champion nor a
Pi-returned stronger bot. The Pi banking job `economic-bank-adapter-01` ended
`coding_failed` (worker time limit), with no candidate SHA; its specified API
was implemented locally after that terminal failure.

The hypothesis is that a connected economic strategy can address the leader
replay findings better than isolated recovery patches. Bot now calls a new
economic runtime. It ranks complete earning/capture/delivery cycles, retains
semantic commitments and complete routes, handles capture roles and compatible
stationary defense, and performs each action through the shared ledger. It
removes the old solo-clear-time rejection and competing legacy dispatcher.
Static delivery estimates and the single origin field are shared with route
extraction. Ranking uses actual item metadata and the separately verified
default Tribute duration model. Unpriced estimates remain contact options.

Banking uses fresh public SDK checks and one issued operation per decision.
Enemy locks are basic/reset work, own carried locks are optional preparation,
and a void submission return needs a fresh observed channel. Protected channels
are preserved. There is no blanket wait solely because another ally submits.
Physical-access waits require observed allied blockers and actual progress;
deadlines and attempts survive recreation. Evidence-based reopening is bounded
to one failed option revalidation per dispatch. Death clears route geometry
while retaining effort, and planner exhaustion releases the failed task.

The actual-SDK integration fixture now links the real banking module. It has
230 assertions covering capture, fields, owner, route, service, dispatch and
banking, including move/submission, two lock hits separated by a reset, own
lock/submission, false use, checked submission errors, rollover, active channel
preservation and immediate stationary winning starts. It still uses an explicit
recovery takeover double. Actual recovery/transaction/service/optional/owner/
arithmetic checks also exist separately. Native checks do not prove game fuel,
peak memory or strength. Full WASM build and measured admission are next.

No games, server uploads or ranked changes have been made for this draft.

then permits the separately predeclared direct 12-game original-champion screen
and unchanged broader strength development/confirmation protocols. Do not
