# CAMBC upstream audit

SDK and runtime checked on 3 November 2026; refreshed handbook and C++ API exports imported on 4 November 2026. This records verified upstream facts and limits; it does not establish that every retained strategic assumption is optimal.

## Release and provenance

PyPI lists **4.0.0** as the latest CAMBC release, released 25 October 2026; its Windows wheel was uploaded 26 October. The repository originally pinned 2.1.6. PyPI's trusted-publishing record identifies `cambattlecode/cambc2026a` commit `44476761e58a564b222a7059875dc3f5e976e0b9` as the 4.0.0 publisher. The Windows wheel SHA-256 is `5e42dc4744f3456fa00cc9602783f905b9a2eee9fcfc59e72ed77c4066abaa5a`. Sources: [latest release listing](https://pypi.org/project/cambc/), [4.0.0 files and provenance](https://pypi.org/project/cambc/4.0.0/).

The audit used a reference project generated by the official 4.0.0 CLI under the ignored `.cambc/upstream-4.0.0/` directory. The checked-in SDK provides the reproducible API reference; the SDK files now match that generated project byte-for-byte. The workspace pins both package and SDK to 4.0.0. The current 86 published maps were added without removing the nine existing maps.

## Documentation limits and preserved history

Direct retrieval of the [event handbook](https://2026a.battlecode.co.uk/game/handbook) was initially blocked: its application assets returned HTTP 403. On 4 November the user supplied freshly downloaded `GameRules.md` and `BotAPICpp.md` in Downloads. These now replace the older repository exports. The official engine source repository remains inaccessible through the available GitHub connection; the documents supply rules evidence, rather than an independent engine-source verification of every interaction.

[GameRules.md](GameRules.md) now documents all fourteen item families, including the previously missing passive formulas. The [runtime snapshot](runtime-4.0.0.json) captures all exposed settings, 84 item designs, two consumables, 13 champion designs including ability metadata, and six camp base-stat designs. All champion stat rows in the supplied export match the probe. The handbook calls clusters non-attacking with range zero; the engine exposes internal range three with zero Strength. Both facts are recorded without treating that internal field as an attacking threat.

The imports retain their supplied content with small editorial corrections: source annotations, the Greed exception in the repeated shard explanation, the cluster-range distinction, and the valid unqualified C++ `debug_block` example. Original downloaded files remain untouched. Original SHA-256 values:

The refreshed rules clarify that Capture Emblem holders cap the remaining capture countdown at three, Prospector bonuses apply to each holder's own cluster-reward share, and Collectors counts unique completed families. They also clarify that camps sleep after two turns without an in-range target and that the first draft turn receives 100 times normal fuel. An isolated Python probe observed 249,620,293 fuel remaining near the start of draft, consistent with the documented 250,000,000 initial allowance (100,000 base × 25 Python × 100 draft). No probe errors were logged. Strategy capture descriptions and retained language API fuel descriptions were reconciled with these rules.

Strategy documents are proposals. In particular, `docs/strategy/meta_strategy.md` was an earlier implementation brief: its old 2.1.6 blocker and Python-only description were replaced with the current compatibility status. The current leader-party documents govern intended bot behavior. Ladder observations in `docs/strategy/analysis.md` remain explicitly dated snapshots, not current rankings.

No files outside documentation/SDK should be deleted as part of this audit. Existing user changes and unrelated files must remain intact.

## Validation and remaining bot behavior

- `uv sync` installs 4.0.0; `uv lock --check --offline` confirms the dependency lock matches.
- Both existing bots build against 4.0.0 in debug and release mode. The Python draft now includes all twelve named choices. The C++ draft preference order is preserved.
- A 100-round debug match on `00ambush` completed without logged bot errors.
- A complete 2,000-round release match on `00monolith` finished with zero VM crashes for both teams. The C++ bot caught four `Known occupied destination` errors before its stdout log cap and scored zero tributed gems; the Python bot scored 763. This demonstrates that builds and host bindings work, but does not establish that the existing C++ strategy/pathfinding works correctly. These movement errors and lack of progress remain an existing-bot issue to investigate separately; no strategic rewrite was made during the SDK audit.
- The isolated draft probe selected Heart of Ruin and queried every champion/camp design without a traceback.
- Rust and OCaml SDKs are included because their templates and API references already existed. No Rust/OCaml bot was built; `cambc.toml` continues to enable Python and C++ only.
- The Python type-checker root now lists only the bot directory that exists.

[API additions](api/SDK_4.0.0.md) cover item selectors, capture-state records, and the current source reference for each language. C++ now uses the user's refreshed API export. Python, Rust, and OCaml retain earlier reference content with enum, fuel-description, and debug-example corrections; they have not been freshly re-exported.

A pre-existing deletion of `docs/strategy/leader_party/team_plan.md` was left untouched. This update did not delete any files.
