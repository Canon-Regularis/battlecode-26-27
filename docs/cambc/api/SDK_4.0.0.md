## Item selection

The SDK contains 84 item types: fourteen families, three stats, and shard/emblem variants. Families are Monster, Power, Durability, Treasure, Jungle, Home, Bruiser, Tribute, Capture, Prospector, Hunter, Skirmish, Greed, and Collectors. Stats are Strength, Focus, and Health. Prefer the family/stat selector to constructing raw item IDs.

```python
item = bc.get_item_enum(bc.ItemFamily.GREED, bc.ItemStat.HEALTH, shard=False)
```

```cpp
auto item = bc::get_item_enum(bc::item_family::greed, bc::item_stat::health, false);
```

```rust
let item = bc::get_item_enum(bc::ItemFamily::Greed, bc::ItemStat::Health, false);
```

```ocaml
let item = get_item_enum ~shard:false Item_family.Greed Item_stat.Health
```

Python and OCaml default to selecting a shard. Rust requires the boolean argument; C++ defaults it to true. The selector returns an item type, without buying anything. Use item design metadata for `cost`, `combine_count`, result, stat points, passive kind/magnitude, and purchasability. Greed requires 25 shards; all other current families require five. Emblems are not directly purchasable. Item-passive enums now include Tribute, Capture, Prospector, Hunter, Skirmish, and Collectors.

## Camp-group capture progress

Lifecycle queries (`state()`) and capture-progress queries (`capture_state()`) serve different purposes. A group's lifecycle is alive, reward available, or respawning. The new capture query reports a countdown and a status relative to the querying team. Group visibility is required; the occupants themselves may remain hidden. It does not identify an unseen capturing champion.

| Python `CampGroupCaptureType` | Value | C++ `map::camp_group_capture_type` | Rust `CampGroupCaptureType` | OCaml `Camp_group.capture_type` |
| --- | --- | --- | --- | --- |
| `NO_CAPTURE_AVAILABLE` | 0 | `no_capture_available` | `NoCaptureAvailable` | `No_capture_available` |
| `ALLY_CAPTURING` | 1 | `ally_capturing` | `AllyCapturing` | `Ally_capturing` |
| `CONTESTED` | 2 | `contested` | `Contested` | `Contested` |
| `ENEMY_CAPTURING` | 3 | `enemy_capturing` | `EnemyCapturing` | `Enemy_capturing` |
| `CAPTURE_AVAILABLE` | 4 | `capture_available` | `CaptureAvailable` | `Capture_available` |

Python: `group.capture_state() -> game_map.CampGroupCaptureState`. C++: `group.capture_state() -> map::camp_group_capture_state`. Rust: `group.capture_state() -> Result<CampGroupCaptureState>`. OCaml: `Camp_group.capture_state group`. Each record has `timer` and `state`; when not capturing, the timer is the configured maximum. Hidden-group queries propagate visibility errors.

## Other compatibility details

- Heart of Ruin is draft choice 11 and champion type 12. Cassi and Issac remain one draft choice but two bodies. Use named enum members.
- Camp state is one of dead, awake (`ALIVE`), or asleep. `is_alive()` includes asleep camps. Awake/asleep occupancy queries exclude dead camps; these are separate from group lifecycle and capture status.
- Vision now includes a single-tile `in_vision` query and awake/asleep camp masks, including variants that write into an existing bitboard. Ward `owner()` exposes the owning champion.
- Python rule constants are loaded lazily from the engine; do not import the bot SDK into desktop CPython to query the game. Run queries inside a compiled bot.
- `debug_block` runs only in debug builds and is skipped on the competition platform. Keep gameplay decisions outside it. Use the unqualified C++ macro, Rust `bc::debug_block!`, Python `bc.debug_block(fn)`, or OCaml `debug_block f`.
- `move_towards` treats its target as free when planning, but the engine validates the landing tile. An already known blocked destination raises an error; a newly revealed obstruction can return false. Filter occupied destinations before moving.
- Official 4.0.0 starter templates still randomly choose from IDs 0–10. They remain byte-for-byte upstream. The repository's Python bot explicitly includes all twelve named choices.

SDK sources are included for all four documented languages. Enable the languages needed by your bots in `cambc.toml`. Rust and OCaml bot builds have not been validated as part of this update.
